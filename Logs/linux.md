## Зачем тестировщику grep и работа с терминалом

QA-инженеры часто думают что их работа — «открыть UI, проверить что кнопка
нажимается». На практике **80% серьёзной работы** происходит за кулисами:
ты копаешься в API, читаешь логи бэкенда, ходишь по серверу — и от твоей
скорости тут зависит насколько быстро баг будет локализован.

### Где это реально нужно тестировщику

**1. Расследование инцидентов на проде**

Случилось «не работает кнопка перевода» → твоя задача узнать **что именно**
сломалось. Бек логирует тысячи строк в секунду. Без grep ты не отличишь
шум от сигнала. Реальные ситуации:

```bash
# Узнать сколько раз падал конкретный эндпоинт за последний час
grep "POST /api/v1/transfers/internal" app.log | grep -c " 500 "

# Найти все ошибки с конкретным userId
grep "userId=a3f9c2e1" app.log | grep ERROR

# Сравнить количество таймаутов до и после релиза
grep -c "Timeout" app-before-release.log
grep -c "Timeout" app-after-release.log
```

**2. Проверка автотестов в CI**

Когда падает 1 тест из 500 — открыть HTML-отчёт занимает 2 минуты.
А `grep -A 20 "FAILED" test-report.txt` находит причину за секунду.

```bash
# Все упавшие тесты в Allure
grep -B 2 -A 5 "FAILED" test-results.xml

# Стектрейсы из логов автотестов
grep -i "assertionerror" test.log | head -10
```

**3. Воспроизведение бага из лога**

Разработчик кидает «у юзера X не работало в 14:32». Ты идёшь в лог,
делаешь `grep "14:32"` — и видишь весь контекст: какой запрос, какой
заголовок, какой ответ.

**4. Анализ нагрузочного тестирования**

После прогона JMeter / k6 / Yandex.Tank — тонны логов. Без терминала
невозможно понять «когда начал падать сервис», «сколько запросов в секунду
он держит», «откуда тайм-ауты».

```bash
# Гистограмма запросов по часам
grep "HTTP " app.log | grep -oE "^[0-9]{4}-[0-9]{2}-[0-9]{2} [0-9]{2}" | sort | uniq -c
```

**5. Тестирование API без UI**

Иногда баг воспроизводится **только** через curl с конкретным заголовком,
которого UI не выставляет. Например — невалидный `Content-Type`, пустой
`Authorization`, нестандартный `User-Agent`. UI не позволит, curl — да.

**6. Подготовка тестовых данных**

«Сгенерируй мне 1000 юзеров с разными типами счётов» → bash-цикл + curl
в одну строку. Postman так не умеет (умеет, но кривовато).

```bash
for i in {1..1000}; do
  curl -X POST http://api/users \
    -H "Content-Type: application/json" \
    -d "{\"email\":\"user${i}@test.local\"}"
done
```

### Почему конкретно `grep` — важный инструмент QA

| Альтернатива | Почему хуже |
|---|---|
| Открыть в редакторе и `Ctrl+F` | Зависает на больших файлах, не считает количества, не комбинируется |
| Открыть в Excel/Notepad++ | То же + не работает на сервере |
| Скачать на локалку и разобрать в IDE | Файл 1 ГБ скачивать долго; на проде ты не имеешь права копировать данные |
| Попросить разраба | Он скажет «иди в логи сама посмотри» — это **твоя** работа |

## Шпаргалка команд (это и есть тема дня)

### Навигация по файловой системе
- `pwd` — где я сейчас (Print Working Directory)
- `ls` — список файлов
- `ls -la` — список с подробностями (права, размер, дата) + скрытые
- `cd папка` — зайти
- `cd ..` — на уровень выше
- `cd ~` — в свою домашнюю папку
- `cd /` — в корень

### Чтение файлов
- `cat file.log` — вывести **весь** файл (для больших — плохая идея)
- `less file.log` — постраничный просмотр (q — выход, / — поиск)
- `head file.log` — первые 10 строк (`head -50` — первые 50)
- `tail file.log` — последние 10 строк (`tail -50` — последние 50)
- `tail -f file.log` — следить за файлом в реальном времени (Ctrl+C — выход)
- `wc -l file.log` — посчитать **строки** в файле

### Работа с файлами
- `touch file.txt` — создать пустой файл
- `mkdir папка` — создать папку
- `cp source dest` — скопировать
- `mv source dest` — переместить / переименовать
- `rm file` — удалить файл (⚠ без корзины!)

### Поиск (grep — главный инструмент QA)
- `grep "ERROR" file.log` — строки содержащие ERROR
- `grep -i "error" file.log` — то же, **без учёта регистра** (`error`, `Error`, `ERROR`)
- `grep -c "ERROR" file.log` — **посчитать** количество строк
- `grep -n "ERROR" file.log` — с **номерами строк**
- `grep -v "INFO" file.log` — **инверсия** (всё КРОМЕ INFO)
- `grep -A 5 "ERROR" file.log` — ERROR + 5 строк **после** (after)
- `grep -B 2 "ERROR" file.log` — ERROR + 2 строки **до** (before)
- `grep -E "WARN|ERROR" file.log` — несколько паттернов через регэксп
- `grep -rn "pattern" .` — рекурсивно по всем файлам в текущей папке
- `find . -name "*.log"` — найти файлы по маске

### Пайпы (объединение команд через `|`)
- `cat file.log | grep ERROR | tail -20` — взять файл → отфильтровать ERROR → последние 20
- `grep ERROR file.log | wc -l` — то же что `grep -c ERROR` (посчитать)
- `grep ERROR file.log | head -5` — первые 5 ERROR
- `grep ERROR app.log | sort | uniq -c | sort -rn | head` — топ-уникальных ошибок

### curl — HTTP-запросы из терминала
- `curl -i URL` — GET-запрос с заголовками ответа
- `curl -s URL` — silent (без прогресс-бара)
- `curl -X POST -H "Content-Type: application/json" -d '{"key":"value"}' URL` — POST с JSON
- `curl -o out.json URL` — сохранить ответ в файл
- `curl -H "Authorization: Bearer xyz" URL` — добавить заголовок
- `curl -w "%{http_code}" -o /dev/null -s URL` — **только** статус-код (без тела)

## Шаги задания

### Шаг 1. Базовая разведка

Открой Git Bash в папке `learning/day-5-linux` (там где лежит `app.log`).

```bash
# Где я?
pwd

# Что в папке?
ls -la

# Размер файла
ls -lh app.log

# Сколько строк
wc -l app.log

# Первые 5 строк — посмотри как выглядит формат
head -5 app.log

# Последние 5 строк
tail -5 app.log
```

⚠ Не пытайся открыть `app.log` в Notepad — он зависнет на 35 МБ. Используй
`less app.log` для просмотра (выход — `q`, поиск — `/слово`, далее — `n`).

### Шаг 2. Считаем уровни логирования

Сколько каждого уровня в логе?

```bash
grep -c "INFO" app.log
grep -c "WARN" app.log
grep -c "ERROR" app.log
grep -c "DEBUG" app.log
grep -c "FATAL" app.log
```

⚠ Внимание: `grep -c "INFO"` посчитает **любые** строки где встречается «INFO» — а не только записи с уровнем INFO. Если хочешь точнее — добавь пробелы вокруг:
```bash
grep -c " INFO " app.log
grep -c " ERROR " app.log
```

### Шаг 3. Посмотри последние 20 ошибок

```bash
grep "ERROR" app.log | tail -20
```

### Шаг 4. Найди таймауты

```bash
# Без учёта регистра (Timeout, timeout, TIMEOUT)
grep -ic "timeout" app.log

# И посмотри что это за таймауты
grep -i "timeout" app.log | head -10
```

### Шаг 5. Дополнительные находки

```bash
# Сколько NullPointerException?
grep -c "NullPointerException" app.log

# Сколько Connection refused?
grep -c "Connection refused" app.log

# OutOfMemory случаи
grep "OutOfMemoryError" app.log | head -5

# Сколько неудачных логинов?
grep -c "Failed login" app.log

# Какие сервисы чаще всего падают (топ-5)?
grep "ERROR" app.log | grep -oE "Connection refused.*" | sort | uniq -c | sort -rn | head -5
```
